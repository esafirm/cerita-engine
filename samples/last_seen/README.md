# Seawall

A full-length mystery built on Cerita Engine: Raka has seven days to rebuild the last week of Sekar, a podcaster
who vanished on the North Jakarta coast. Indonesian first, with English alongside. The plan is
[`specs/last-seen.md`](../../specs/last-seen.md).

Players see the name Seawall. It was called Last Seen until 1.1.0, and the code still is: this folder, the `last_seen`
Dart package, the `*-last-seen` make targets and the package ID `id.twk.lastseen`.

## Layout

| Path | What |
| :--- | :--- |
| `story/` | The `.cerita` scripts and `cerita.yaml`, `profiles.yaml`, `channels.yaml`. Edit these |
| `assets/story/` | The compiled JSON plus art and audio. The JSON is generated by `make story` and committed |
| `art/style-guide.md` | Look, framing, prompt templates and the cast sheet |
| `art/prompts/` | One prompt per generated image, so any image can be made again |
| `art/placeholders.txt` | Every placeholder made so far, for `tools/placeholders.sh --list` |
| `tools/` | The image, voice and placeholder scripts, `make-icon.sh` for every app icon size from `art/icon/icon.png` (and `--alt <name>` for the alternate icons) and `ui-sounds.sh` for the menu blips |
| `assets/wallpapers/` | The bonus wallpapers in Extras, part of the full game. Prompts in `art/prompts/wallpaper_*.txt` |
| `assets/icons/` | The previews in Extras → App icon, where players pick the launcher icon (Android and iOS). The alternates are part of the full game, see the decisions log |
| `lib/ui/` | The 90s PC look: `RetroSkin` for the story, the framed `RetroWindow`, the theme and the menu blips |
| `assets/fonts/` | DotGothic16, the dot font (SIL OFL 1.1) |

## Workflow

Run these from the repo root:

```bash
make story            # compile story/ to assets/story/, then lint and print playtime stats
make story-check      # what CI runs: stale JSON or script errors fail
make placeholders     # fill missing art and sound with placeholders
make voice ARGS=--dry-run   # list the voice lines to render and what they cost
make voice            # render them with Gemini TTS through treg
make run-last-seen    # run the app
```

One image at a time, from its prompt in `art/prompts/<name>.txt`:

```bash
samples/last_seen/tools/codex-image.sh bg/bg_seawall_night.webp
```

`tools/placeholders.sh --list` prints the placeholders no real asset has replaced yet.

## Release builds

`make release-last-seen` builds the Play Store bundle and per-ABI release APKs, signed with the upload key. The key
is committed encrypted as `android/upload-key.tar.enc` (AES-256, PBKDF2). Its passphrase is in the owner's password
manager and nowhere in the repo. Restore it once per checkout:

```bash
samples/last_seen/tools/upload-key.sh decrypt    # asks for the passphrase
```

That writes `android/key.properties` and `android/app/upload-keystore.jks`, both git-ignored. For a script or CI,
set `LAST_SEEN_KEY_PASSPHRASE` (or `LAST_SEEN_KEY_PASSFILE`) instead of typing it. After rotating the key, run
`upload-key.sh encrypt` and commit the new blob. A Play listing can only be updated with the key it started with.

Without `key.properties`, release builds are signed with the debug key, which installs fine for testing but can't go
to a store. iOS builds need a team set in Xcode (`ios/Runner.xcworkspace`) and Xcode 16 or later. Xcode 15 can't
build on macOS 26, see the decisions log.

## Full game purchase

The Prologue, Day 1 and Day 2 are free. One non-consumable, sold through RevenueCat (`purchases_flutter`), opens
Day 3 to Day 7 and every ending. The code is in `lib/store/`: `FullGame` decides and is what the story's gate asks,
`RevenueCatStore` talks to the SDK, and `Paywall` is the store page shown over the story at Day 3 and from the title
menu's *Unlock full game* entry. Players who reached Day 3 in 1.0.0, before the game was sold, keep the full game.

RevenueCat setup, in the dashboard:

- One non-consumable product per store (App Store Connect, Play Console), attached to the entitlement `complete_content_bonus`.
- A package for it in the current offering, preferably the Lifetime package. The paywall shows its store price.

The public SDK keys stay out of git. Put them in `revenuecat.json` next to this README (git-ignored, copy
`revenuecat.example.json`), and the `make` targets pass it with `--dart-define-from-file`. Without a key for the
platform, and on the web, the store is off: Day 3 stays closed and the paywall says the store isn't available.

For testing, the key can be RevenueCat's Test Store key (`test_…`), one key for both platforms. Purchases then show
a RevenueCat dialog to pass, fail or cancel, with no store account needed. It works in debug builds only: the SDK
crashes on purpose in any other build that uses one. So `make release-last-seen` refuses it (except with
`TESTER=1`), and other non-debug builds ignore it and keep the store off. Put the production keys in before a store
build.

| Build | Paid days |
| :--- | :--- |
| Debug (`make run-last-seen`) | Open. Add `--dart-define=LAST_SEEN_TESTER=false` to `flutter run` to see the paywall |
| Profile and release | Closed until bought |
| `make release-last-seen TESTER=1` | Open, for playtest APKs. Builds no store bundle |

The admin sheet's *Unlock everything* fills the chapter list but doesn't open paid days. Use a tester build, or a
store sandbox / Play license tester account to test the purchase itself.
